01 the primitive

One primitive: a graded loop

A maker does the next work item; an independent verifier grades the artifact against hard, pre-frozen criteria; the gaps become the next maker's input; repeat until every criterion passes. The model is stateless — the system isn't.

the hard gate
A loop refuses to start until the goal has measurable, verifier-checkable done-criteria — 7 required fields in GOAL.md. "Make it better" is rejected: an unmeasurable gate means the verifier can never return PASS and the loop burns budget without converging.

"Tracks each project separately"

Every goal scaffolds its own directory under the project root. Dispatch scans self-learning-loop/*/STATE.md at session start: none → init a new loop; one → resume it; several → resume the one you name. Loops coexist; each carries its own goal, memory, and artifacts.

Resume takes one line — continue the loop <name> — and never re-interviews. GOAL.md is the gated source of truth, so criteria can't drift between sessions.

03 your ask · 2
ships today one honest caveat

Artifacts each step · memory that reads both ways

The step outputs live in artifacts/. The narrative and the graded trail live in STATE.md — one line written immediately after every verdict, so a killed session loses at most one iteration.

# one STATE.md line per step — delimited grammar
3.2 · class:retrieval · tier:sonnet · maker: added BM25 · verdict: gaps(2): recall, dupes
3.3 · class:retrieval · tier:opus · maker: dedup+rerank · verdict: PASS
the caveat — say it plainly
"Machine-readable" here means markdown conventions: a fixed log grammar plus JSON-schema verifier verdicts. It's diffable in git and parseable with a regex — but it is not yet a typed store. That's one of the seams (slide 06).

Memory isn't a flat log — it's a promotion ladder. A finding climbs only as evidence accrues, so the next session consults verified facts instead of re-deriving them.

04 your ask · 3
partial — the honest one

Purpose-built skills for training & analysis

Lessons → skills

Project-scoped lessons distill into a generated project skill; cross-project ones append to a shared global-learnings.md with used:/last: usage suffixes. Promotion into a real skill stays approval-gated.

The structure pass

Every 3 sessions a strong model re-reads the whole trajectory to merge duplicate memory, retire dead weight, and promote repeated patterns — the loop's own analysis loop. Read-only, proposal-only.

Self-tuning routing

A task class that fails verification ≥2× at its model tier auto-promotes a tier up — never above the session ceiling. The router learns which work is hard.

where "partial" is honest
The analysis half is real and running — the loop grades and restructures its own memory. The training half is latent: the iteration log is a natural (prompt → artifact → verdict) dataset, but nothing yet extracts it as training/eval data. That's the highest-value seam on the next slide.
05 why risk labs

The core is already an eval harness

You flagged this for risk labs — and the load-bearing invariant is exactly the one an eval needs: the maker is never the verifier.

the problem it designs around
A model grading its own output favors conclusions consistent with what it just wrote. Self-graded "PASS" is worthless as a signal.
the fix, enforced
The verifier is an independent subagent that receives only the artifact + criteria + rubric — never the maker's reasoning, chat, or this conversation. Context-isolated grading, no exceptions.

Frozen criteria

The rubric is gated before the first run and can't drift — a reproducible bar.

Audited trail

Every attempt and verdict is logged with evidence — a full record of what was tried and how it scored.

Swap the maker

Point the maker slot at the model-under-test and the verifier is your grader. Same harness, eval mode.

06 the seams

"We have most of this — just needs connecting"

Agreed. Three seams are genuine stubs. Each is connective work over primitives that already exist — not new architecture.

seam 1

Cross-loop analytics

Each self-learning-loop/*/ is siloed. No rollup that reads every STATE.md to answer "which classes fail most, where does budget go, which loops stalled." A read-only aggregator over a format that's already fixed.

seam 2

Training-data export

The iteration log is a labeled dataset waiting to be emitted — (prompt, artifact, verdict, gaps) as JSONL for eval sets or preference data. The signal is captured; nothing serializes it out.

seam 3

Shared memory store

global-learnings.md is a flat file; a graph store already exists elsewhere in the stack, unwired. Connecting them turns per-loop lessons into a queryable org-wide memory.

the shape of the work
All three consume the loop's existing outputs and emit alongside them. None touches the graded-loop primitive. This is plumbing between components you already own — which is precisely what you said.
07 driving it

Start it in one line

Init

build a loop system to do X — the skill interviews for the hard gate, scaffolds self-learning-loop/<name>/, wires scoped permissions, and runs session 1.

Resume

continue the loop <name> — reads STATE.md, runs the next session, no re-interview. Auto mode self-continues within a budget ceiling and halts + notifies on any irreversible or outward action.
