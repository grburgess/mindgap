# todo-mindmap

Ideas and todos live in the graph, not in a list. Each one hangs off the project it
belongs to, so reviewing todos also surfaces the surrounding context, and closing one
leaves a trail instead of a deletion. Graph writes obey `AGENTS.md`.

## Dispatch

| The user says | Verb |
|---|---|
| "todo:", "idea:", "we should X", "remind me to X", "don't let me forget X" | CAPTURE |
| "what's outstanding", "what are my todos", "what should I work on", "anything open on X" | REVIEW |
| "that's done", "finished X", "drop that one" | CLOSE |

Inside a loop-system or meta-trainer session → **stop**, those own their memory protocol.

## Node contract

| Field | Value |
|---|---|
| `id` | `todo-<slug>` |
| `type` | `todo` |
| `title` | imperative one-liner |
| `body` | what / why / what "done" means; `[[wiki-links]]` to related nodes |
| `tags` | `todo` + **exactly one** `status:open\|doing\|done\|dropped` + area tags + optional `someday` |
| `confidence` | `1.0` — never overloaded as priority |
| `created_by` | `skill:todo-mindmap` |
| `urls` | optional — Jira ticket, PR, file path |

Edges — **≥1 always, explicit in the payload, never an island**:

| rel | target | cardinality |
|---|---|---|
| `part_of` | project / repo / loop node | exactly one (primary anchor) |
| `relates_to` | concepts, papers, decisions it touches | 0..n |
| `depends_on` | blocker — a node or another todo | 0..n |
| `resolved_by` | what closed it — jira-ticket, page, repo node | 0..n, added at CLOSE |

Wiki-links alone are not durable: `sync_wiki_edges` prunes derived `mentions` edges when
the body changes. Anchors go in the payload `edges`.

## CAPTURE

1. `mindgap_find` on slug fragments + title words. A close match → upsert **that** id; never mint a near-duplicate.
2. `mindgap_find` / `mindgap_context` to resolve the anchor project.
3. One `mindgap_ingest` call: node + all edges (validated whole-payload, no partial commit).
4. Reply with the id and the anchor.

No plausible anchor exists → create the project node in the same payload rather than
orphan the todo. **At most one clarifying question** — capture that interrogates stops
being used. A missing anchor is worth asking about; a missing done-criterion is not.

```json
{
  "created_by": "skill:todo-mindmap",
  "nodes": [{
    "id": "todo-decide-image-encoding",
    "title": "Decide image encoding: 3-channel RGB vs 4-channel RGB+mask",
    "type": "todo",
    "body": "Open decision blocking [[thumbnail-classifier]] setup. Done = one encoding chosen with a stated reason.",
    "tags": ["todo", "status:open", "thumbnail-classifier"],
    "confidence": 1.0
  }],
  "edges": [
    {"src": "todo-decide-image-encoding", "dst": "thumbnail-classifier", "rel": "part_of"}
  ]
}
```

## REVIEW

1. `mindgap_find` with `type="todo"`, `tag="status:open"` (exact tag-token match, ordered by `updated_at` DESC). Ask a second time with `tag="status:doing"` when the user wants in-flight work too.
2. Group by `part_of` anchor. Show id, title, age, anchor. Scope to one project when the user names one.
3. When the user picks one, `mindgap_context <id>` — that is the "show me the relevant info" step.

## CLOSE

Never close a todo the user did not ask you to close. If work you just did happens to
match an open todo, **propose** the close and wait for a yes. `status:doing` is set the
same way.

1. `mindgap_get_node` — read the current title, tags, urls, and confidence.
2. Build the new tag list in memory: swap `status:open`/`status:doing` → `status:done` (or `status:dropped`), keep every other tag.
3. `mindgap_add_node` with `replace=true`, the **full** tag list, the full urls list, title and confidence verbatim, and the body **appended** with:
   `**Done:** YYYY-MM-DD — <one-line outcome>`
4. Add the `resolved_by` edge when an artifact exists (`mindgap_link`, or an `edges`-only `mindgap_ingest`).

**The trap:** a normal upsert **unions** tags, so ingesting `status:done` onto an open
todo leaves `status:open` in place and the todo stays outstanding forever. Only
`mindgap_add_node` with `replace=true` overwrites the tag list — and because
`replace=true` also replaces `urls`, `title`, and `confidence`, resend the existing ones. `mindgap_ingest` and
the `mindgap add` CLI cannot flip a status.

**Append the body, never rewrite it** — a rewrite drops wiki-derived `mentions` edges for
links no longer present.

Any tag removal — re-opening a terminal todo, dropping `someday` — has the same constraint: only `mindgap_add_node` with `replace=true` and the full tag list can do it.

## Boundaries

- Not a scheduler: no due dates, no reminders, no cron. The graph is the record; recall is on demand.
- No priority field.
- `idea` belongs to the research loops (steal/synthesis nodes) — this skill never writes it.
- Does not touch the SessionEnd capture hook or its `task`/`next-action` nodes.
