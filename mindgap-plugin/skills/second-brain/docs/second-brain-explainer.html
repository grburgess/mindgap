The loop-system memory discipline — layered retrieve, work, distill — for tasks that aren't loops. Every substantive task starts by pulling what you already know and ends by paying its learnings back. The returns compound.

01 the cycle

One cycle, every task

The graph sits at the center. Each task orbits it once: retrieve context in, work, update learnings out. Maintain runs off-cycle, keeping the graph honest.

Retrieve

Five layers pulled top-down before work starts — global rules, project ledger, adjacent loop state, the graph 2–3 hops out, reusable ctx/.

Update

Learnings routed to exactly one destination; deliverables registered as graph nodes; inbox swept. Cheap by default, gated where reach is global.

Maintain

The absorbed mining modes — connect latent links (adjudicated, gated write-back), learn frontier, enrich. On request, not per task.

02 retrieve · layered pull

Five layers, top-down

Mirrors loop-system RESUME step 1, decoupled from loops. Context diet applies: inline what's relevant, never everything. Any global row that informs a decision gets its used:/last: bumped.

1 · global

mindgap_find task keywords + tag global-learning; matching global-learnings.md rows.

2 · project

<project>/.claude/PROJECT-LEARNINGS.md when present — the ledger loop-distill maintains.

3 · task-adjacent

self-learning-loop/*/STATE.md whose GOAL matches the topic. Read-only; never touch a live loop.

4 · graph

mine enrich on the seed topic — the RWR-ranked 2–3-hop subgraph, not a 1-hop keyword hit. find/context for specifics.

5 · ctx/

Reusable prompts, templates, rules from ~/second_brain/ctx/ — found via their graph index nodes.

03 update · tiered write-back

Cheap by default, gated where reach is global

Routing follows loop-distill's promotion table: one destination per learning, dedup against every destination first. A stale ledger row costs one project; a stale global row costs every project — so verification cost scales with reach.

deliverables become nodes
Every artifact — deck, report, doc — is registered in the graph: type=page, tag artifact, url → file path, edges to the concepts it embodies. Past work becomes retrievable by enrich.
same rows loop-distill audits
Ledger rows use the identical used:<n> last:<date> format — loop-distill stays the single project reconciler, auditing loop and non-loop learnings alike.
04 the stores · ~/second_brain/

Visible folders, hidden database

One Finder-friendly drop target. Drag a file to inbox/ — that's the whole capture gesture. Ingest extracts the knowledge into the graph, moves the file to raw/, and stamps the source node with the archived path. The db stays hidden in ~/.mindgap/; you never touch it.

~/second_brain/
├─ inbox/   # drop zone — ingest sweeps it
├─ raw/     # immutable archive, YYYY/topic/
│           # source nodes url → here
└─ ctx/     # prompts · templates · rules,
            # each indexed by a graph node

# deliberately NOT here:
output/     # artifacts stay in their repos —
            # the graph indexes them as nodes

05 boundary · loop-system

Same memory, different machinery

Loops and one-shot tasks share every memory layer. What differs is the engine on top — and each engine owns its own sessions.

second-brain

One-shot substantive tasks. No per-task state files, ever. Retrieve → work → update, then done. Fires explicitly or proactively on domain work; never for trivial mechanics, never inside a loop session.

loop-system

Multi-session goals with measurable done-criteria. Owns GOAL/STATE, maker/verifier, auto mode. A task that turns out to need persistent cross-session state is the signal to hand off here.

the handoff rule
Needs multi-session state or a measurable gate → it's a loop. Second-brain never imitates loop machinery — it hands off.
